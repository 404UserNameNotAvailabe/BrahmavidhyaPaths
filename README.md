# Brahmavidya Path Checker

A private archive of **"Brahmavidya" paths**: the short handwritten messages HH Mahant Swami Maharaj gives once a day during **Dhanurmas** (16 Dec – 14 Jan). The tool answers one question before a new path is used: *has this, or something close to it, already been given?* It also lets a small team (2–3 people) browse, search and curate the archive.

## Domain rules (read before changing data or schema)

### Seasons
- A **season** runs **16 Dec → 14 Jan**: 30 days, one path per day. It is named by its start year, so `season 2016` = "2016–17" (16 Dec 2016 – 14 Jan 2017).
- `messages.season` and `messages.year` are **generated by Postgres** from `message_date`. Never write them from code.
- Any date outside the window is rejected. That rule lives in **three places, which must stay in sync**:
  1. `Backend/taxonomy.py` → `in_season()` / `check_season_date()` (API validation; `/import` reports it per row)
  2. `Backend/sql/schema.sql` → check constraint `ck_messages_dhanurmas`
  3. Frontend `src/lib/season.ts` (the Season + Day picker and CSV import)

### Fields on a path (`messages`)
| Field | Meaning |
|---|---|
| `message_text` | The path in Gujarati, exactly as written. `normalized_text` is generated from it and must be unique, which is how exact duplicates are blocked. |
| `message_date` | The day it was given (inside the season window). |
| `link` | **Original source**: the handwritten path image on baps.org (see below). It must be an http(s) URL (`ck_messages_link`). |
| `tags` | The only grouping field. **There is no category** (it was merged into tags in Oct 2026). |
| `source` | Attribution text, e.g. "શ્રીજી મહારાજ". Auto-detected from a trailing "– name" when blank. |
| `is_favorite` | Starred by an editor. |
| `embedding` | Optional Vertex AI vector for "Deep check". It is filled in the background, and `NULL` means pending. |

### The original links (baps.org)
- BAPS publishes each season as a news page called "'Brahmavidya' – Dhanurmas Messages from HH Mahant Swami Maharaj YYYY-YY". The page has a gallery with one image per day, e.g. `https://www.baps.org/Data/Sites/1/Media/GalleryImages/32361/WebImages/20241216_brahmavidyapath.jpg`.
- Every archived path's `link` points at **its own day's image**. The full list is in `Backend/sql/links_baps.sql`, which can be re-run safely and only fills empty links.
- **Adding a season:** store the text in **Gujarati script** (Hindi in Devanagari, English as written), *not* the romanised text on the news page, because Check compares script-to-script. Transcribe from each day's image and check it against the romanised list. Note that the 2025–26 page lists them **newest first** (14 Jan → 16 Dec) while 2024–25 lists oldest first, so always confirm the order against the date printed on each image ("બ્રહ્મવિદ્યાનો પાઠ – N", day N = 15 + N Dec).
- **Image filenames are irregular** (`_001`, `__1_`, `_copy`, and numbered by day instead of date in 2016–18). Never guess a URL; read it from the season page.
- The **news pages sit behind a Cloudflare bot check**, so `curl` gets 403. Open them in a normal browser. The image URLs themselves load fine.

### How "Check" decides
Check is deliberately **literal**, so its results can be explained: `Backend/matching.py` + `POST /check`.
- It compares word coverage (the share of the new path's words found in an archived path) and the longest shared run of consecutive words.
- Results are `exact`, `strong`/`some` (an overlap worth reviewing) or `contains` (short queries of ≤6 words are treated as a search).
- The overall verdict is `exact` / `review` / `contains` / `new`.
- **Deep check** (`?semantic=true`) adds Vertex AI embeddings and labels a meaning match of ≥0.87 as `reworded`. It is opt-in because it costs a network call.

## Working on it

- **Run the backend locally:** see `Backend/SETUP.md`, which covers `.env`, schema and the API contract.
- **Deploy:** see `DEPLOY.md` for the full runbook.
- **Schema:** `Backend/sql/schema.sql` is the single source of truth and is **applied automatically on every API start**. Every statement in it must be idempotent (`IF NOT EXISTS`, guarded `DO` blocks). Data fixes go in separate files under `Backend/sql/`, never in `schema.sql`.

### Release order
The frontend depends on the API contract, so **ship the backend first**:
```bash
# 1. Backend (on the server)
cd /opt/brahmavidya/app && git pull && systemctl restart brahmavidya-api   # schema auto-applies
# 2. Frontend (from the brahmavidya-insights repo, on main)
bun run build && bunx wrangler deploy
```
Neither repo has CI. Merging a PR deploys nothing.

### Repo-root leftovers
`baps_extractor.py` (a Selenium scraper), `brahmavidya_*.csv` (romanised text, not the Gujarati archive) and `debug_page_*.html` are from the original data collection. They are not used by the app.
